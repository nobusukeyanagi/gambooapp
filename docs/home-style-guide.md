# Gamboo ホーム スタイル設計ガイド

## 目的

ホーム画面は、見た目を維持しながら変更箇所を一意に特定できることを重視する。コード行数の削減は目的ではない。責務が明確で、回帰テストに合格する変更を「改善」とする。

## CSS の責務と読込順

`SCR-01_bet.html` の `<head>` で次の順に読み込む。

1. `assets/design-tokens.css`：フォント、サイズ、太さ、余白、色、罫線、角丸、影、コントロール寸法の**唯一の定義元**。
2. `assets/bottom-nav-icons.css`：ボトムナビのSVGアイコンサイズ・形状と有効/無効状態。
3. `assets/app-base.css`：リセット、ページ全体のフォント、アプリ外枠。
4. `assets/home.css`：**ホーム固有の**配置、コンポーネント、状態とレスポンシブ指定。
5. `assets/tap-feedback.css`：共通の押下反応。
6. `assets/ui-consistency.css`：複数画面にまたがる共通コンポーネント。最後に読み込む。

共有コンポーネントの変更は共通CSSを修正する。ホームだけの要件はホーム専用CSSに置く。同じプロパティを両方に重複定義しない。

## JavaScript の責務

- `assets/scroll-controls.js`：スクロール操作の共通制御。
- `assets/home.js`：ホーム固有のバナー、払戻金表示切替、デモ用締切表示。
- `assets/tap-feedback.js`：共通のタップ・押下表現。

ホームHTMLから画面固有のインラインスクリプトを排除し、JSの変更は専用ファイルで行う。スクリプトのDOM実行順序を変えない。共有JSの変更は他画面も確認する。

## 記述ルール

- 共通の値はCSS変数を**直接**参照する。別名変数 `--a: var(--b)` による単純な多段参照を作らない。
- CSS の短い値を流用するためだけにセレクターの特異度を上げない。たとえば `.tab-item.tab-item` を使わない。
- `!important` に頼らず、コンポーネントの責務と状態条件で優先順位を説明する。
- `font-size` と `font-weight` を同時に指定する場合、サイズに一致する `--fw-XX-normal` または `--fw-XX-strong` を参照する。
- メディアクエリは `359px以下` と `330px以下` に集約する。状態・レスポンシブで異なる値が必要な場合のみ上書きする。
- 過去の修正をページの末尾に追加するのではなく、**既存の定義元**を編集する。不要になった旧値は削除する。
- 共有CSSの更新時は、ホーム以外の利用画面への影響も確認する。
- CSSを変更したら参照する `?v=` を更新し、GitHub Pagesのキャッシュを回避する。

## 変更確認

ローカルでは Node.js 24 と Playwright を使用する。

```sh
npm ci
npx playwright install chromium
python3 -m http.server 4173
# 別のターミナルで
npm run check:home
```

`npm run check:home` は次を検査する。

- PostCSS によるCSSの構文解析、未定義変数、重複セレクター、別名変数、サイズ・ウェイトの不一致
- Chromium 上でのJavaScriptエラー、重要なコンポーネントの実際のスタイル
- 296、320、330、331、359、360、390、430、768pxの9画面幅
- ファーストビューとスクロール下部のスクリーンショット（計18枚）

GitHub Actionsの **Verify Gamboo Home** は `main` への関連ファイル変更で自動実行される。

**変更前との画像比較が必要な場合**は、Actions → Verify Gamboo Home → Run workflow で `baseline_commit` に比較したいコミットSHAを入力する。比較では各画像の変更ピクセル比率を測定し、意図しない変更を検出する。

## 品質保証の限界

画像比較は指定した9画面幅・2スクロール位置での検証である。すべての操作順、デバイス、OS、フォント環境での完全一致を保証するものではない。機能改修時は必要な操作テストを追加する。
